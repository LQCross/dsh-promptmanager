# 提示词管理器 Prompt Manager（DSH 插件）

`@local/prompt-manager` v1.2.0 —— DeepSeek Harness 的提示词库插件。

- **设置 → 提示词**：新建 / 编辑 / 删除 / 置顶 / 搜索 / 复制 / **导出 / 导入**。
- **输入框工具行左侧书本图标**：左键弹层搜索，点击把提示词插入草稿（走官方 `inputActions`，可撤销、可继续编辑）；**右键在文件管理器里打开当前会话的工作目录**。
- 数据存在浏览器 `localStorage['dsh.prompt-manager.v1']`，不写 Host 侧文件。

## 目录结构

```
prompt-manager/
├── package.json          清单（含 dsh.bundle.patch / dsh.client / engines.dsh）
├── cordis.patch.yml      插入 Loader 行 prompt-manager
├── index.js              Host 半：apply() 空实现
├── client.js             浏览器半：全部界面、存储、导出/导入逻辑
├── selftest.mjs          导出/导入逻辑自检（Node 直接跑，不开浏览器）
├── locale/en.json        插件管理里显示的英文标题/简介
├── locale/zh.json        中文标题/简介
├── icon.svg              图标
└── README.md             本文件
```

## 安装到另一台电脑

前提：该机器已装 DSH，且 DSH 版本与本机同代（0.2.x）。

1. 把整个 `prompt-manager` 目录复制到目标机任意固定位置，例如
   `D:\CODEENV\dsh-plugins\prompt-manager` 或 `~/dsh-plugins/prompt-manager`。
   注意：**不要放在会被清理的临时目录**，安装后 profile 里是指向该目录的软链接。
2. 在 DSH 里让 Agent 执行：

   ```
   plugin_manager({ action: "install_bundle", target: "<目标机的绝对路径>/prompt-manager" })
   ```

   或直接用 DSH 的插件管理界面安装该本地目录。
3. 返回里应有 `"application": "applied"`、`"warnings": []`。
4. 刷新页面。打开 设置 → 提示词，能看到页面即安装成功。

安装会做的事（了解即可，不用手动）：在 `profiles/<profile>/package.json` 里加
`"@local/prompt-manager": "link:<目录>"` 依赖，并把 `@local/prompt-manager` 追加进
`dsh.profile.bundles`。

## 卸载

```
plugin_manager({ action: "remove_bundle", target: "@local/prompt-manager" })
```

# 数据迁移：导出与导入

## 一、迁移范围

| 迁移 | 不迁移 |
| --- | --- |
| 提示词条目：`id` / `title` / `content` / `tags` / `favorite` / `updatedAt` | 插件代码与 Loader 行（随安装包走） |
| 上述 6 个字段的取值本身 | 搜索框内容、排序状态（瞬时，不落盘） |
|  | 主题 / 语言 / 快捷键 / Settings 其它页 |
|  | 会话历史、附件、Host 侧任何文件 |

唯一的数据源是 `localStorage['dsh.prompt-manager.v1']`，本插件不写其它键、不写磁盘。

## 二、导出文件格式

文件名：`prompt-manager-YYYYMMDD-HHmmss.json`（本地时间）。

```json
{
  "format": "dsh.prompt-manager.export",
  "formatVersion": 1,
  "exportedAt": "2026-11-08T03:07:49.000Z",
  "plugin": { "name": "@local/prompt-manager", "version": "1.2.0" },
  "count": 2,
  "items": [
    {
      "id": "p1abc123",
      "title": "代码审查",
      "content": "请审查以下代码……",
      "tags": ["review", "code"],
      "favorite": true,
      "updatedAt": 1762500000000
    }
  ]
}
```

字段约定（与插件内部存储**完全一致**，导出不新增、不改写任何字段语义）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `format` | string | 固定 `dsh.prompt-manager.export`，用于拒绝外来文件 |
| `formatVersion` | number | 当前为 `1` |
| `exportedAt` | string | ISO 8601 导出时刻，仅作记录，不参与导入 |
| `plugin.name` / `plugin.version` | string | 导出方标识，仅作记录 |
| `count` | number | 与 `items.length` 一致，导入时不作为校验依据 |
| `items[].id` | string | 条目身份，判重唯一依据 |
| `items[].title` | string | 可为空串 |
| `items[].content` | string | 非空，导入的必填项 |
| `items[].tags` | string[] | 可为空数组 |
| `items[].favorite` | boolean | 置顶标记 |
| `items[].updatedAt` | number | 毫秒时间戳，用于排序 |

导入端同时接受**裸数组** `[{...}, {...}]`（便于手工整理或旧 Console 备份），按同样规则校验。

## 三、导入规则（已确认）

1. **两种模式，默认「合并」**
   - 合并：保留本机所有条目；文件里同 `id` 的条目**覆盖**本机那条；文件里的新条目置顶。
   - 替换：本机内容整体换成文件内容（先点一次变「再次点击以确认替换」，再点才执行）。
2. **判重只按 `id`**：`id` 不同即视为不同条目，正文相同也不算重复。
3. **同 id 冲突：文件覆盖本机**（本机对该条的修改会被丢弃，合并前后会显示「覆盖 N 条」）。
4. **文件内重复 id**：同一文件里出现多次，只保留最后一条，其余计入「已合并 N 条」。
5. **任一条无效 → 整体拒绝**，一条都不写入，并提示第几条、什么原因。

逐条容错（不改字段含义，与插件既有 `sanitize` 一致）：

| 情况 | 处理 |
| --- | --- |
| `content` 缺失 / 非字符串 / 全空白 | **无效** → 整体拒绝，提示 `第 N 条 · 缺少内容` |
| 条目不是对象 | **无效** → 整体拒绝，提示 `第 N 条 · 不是对象` |
| `title` 缺失或非字符串 | 存为 `""`（UI 显示「未命名提示词」） |
| `title` 超 120 字 | 截断到 120 字 |
| `tags` 缺失 / 非数组 | `[]` |
| `tags` 里的非字符串或空白项 | 丢弃该项 |
| `favorite` 非 `true` | `false` |
| `updatedAt` 非有限数 | 导入时刻 `Date.now()` |
| `id` 缺失 / 空串 | 生成新 id（不会被判为重复） |

格式错误（整份文件层面，一律不写入任何数据）：

| 情况 | 提示 |
| --- | --- |
| 不是合法 JSON | 文件不是合法 JSON，未做任何改动 |
| 顶层既非数组也非对象 | 文件内容既不是提示词数组，也不是本插件的导出文件 |
| 对象但 `format` 存在且不等于 `dsh.prompt-manager.export` | 不是本插件的导出文件（format 字段不匹配） |
| `formatVersion` 存在且不等于 `1` | 导出文件版本为 N，当前插件只支持版本 1 |
| 对象但 `items` 不是数组 | 导出文件缺少 items 数组 |
| 读取文件本身失败 | 读取文件失败，请重试 |

## 四、完整性与失败处理

- **导出即全量**：`items` 由当前内存/存储中的全部条目规范化后写出，不做过滤、不分页，因此「导出 → 导入（替换模式）」可逐字段还原。
- **先校验后写入**：解析与逐条校验全部通过才进入写入阶段；任何校验失败都在写盘前返回。
- **写入原子性**：写入前读取原值作为快照；`localStorage.setItem` 抛错（配额不足 / 被禁用）时把快照写回，内存缓存按存储重读，界面提示「已回滚，未做任何改动」。
- **不产生重复**：合并模式按 `id` 去重（文件内重复也先去重），替换模式直接以文件内容为准。
- **不损坏数据**：任何失败路径都不写入部分结果；替换模式需要二次点击确认。

## 五、操作说明

**导出**

1. 设置 → 提示词。
2. 点工具栏「导出」，浏览器下载 `prompt-manager-<时间戳>.json`。
3. 页面顶部出现「已导出 N 条提示词」。

**导入（合并）**

1. 设置 → 提示词 →「导入」，选择 JSON 文件。
2. 出现导入面板：文件名、文件内条数、文件内重复 id 合并数、「合并（保留本机）」高亮、以及「将新增 X 条，覆盖同 id 的 Y 条；本机其它条目保持不变。」
3. 点「确认导入」→ 提示「导入完成：新增 X 条，覆盖 Y 条」。

**导入（替换）**

1. 同上选好文件后，点「替换（清空本机）」，面板改显「将用文件内 X 条替换本机全部 Y 条，未导出的本机条目会丢失。」
2. 点一次按钮（变红字「再次点击以确认替换」），再点一次才执行。
3. 成功提示「替换完成：现共 X 条」。

**出错时**：面板不出现，顶部红色提示说明是整份文件的问题还是第几条的问题，本机数据保持原样。

## 六、测试步骤

### 0. 右键打开会话工作目录（v1.2.0）

在任意会话里，把鼠标放到输入框工具行左侧的书本图标上，**右键单击**：宿主会用目录打开路由把该会话的工作目录交给系统文件管理器（Windows 上是文件资源管理器）。按钮的悬停提示第二行写明这一点。

- 目录来源：客户端会话摘要的 `cwd`（与官方 `ui-open-in-app` 同一数据源）；会话没有目录时提示「本会话没有工作目录，无法打开」。
- 打开方式：`GET /open-in-app/apps` 取宿主可用的目录应用列表，按 `explorer` → `finder` → `filemanager` 选平台文件管理器，再 `POST /open-in-app/open`。宿主自己会校验路径是绝对路径且确实存在。
- 失败提示：宿主没有文件管理器、或拒绝了该路径 → 「打开失败……」。宿主侧把「在文件管理器中打开」当作一次委托交接（Explorer 退出码 1 也算已交接），所以本插件只判断路由是否接受，不判断窗口是否已弹出。
- 已知边界：这是**直接动作**（右键即打开），没有二级菜单；若以后要加更多右键项，再换成共享的 `contextMenus` 菜单。

验收：会话有工作目录时右键 → 资源管理器打开该目录；会话无目录时右键 → 只有提示、不弹窗、不报错。

### 1. 逻辑自检（无需浏览器，30 秒）

```powershell
node selftest.mjs
```

预期最后一行 `14 checks passed`。覆盖：信封字段、导出→导入逐字节往返、裸数组、合并覆盖语义、替换语义、文件内重复 id、缺字段补齐、超长截断、非法 JSON、空 content 定位、非对象条目、format/version/items 校验、写入成功、写入失败回滚。

### 2. 界面往返（合并模式，不破坏现有数据）

1. 设置 → 提示词，建 2 条测试提示词（其中一条置顶、带标签）。
2. 点「导出」，确认下载文件名形如 `prompt-manager-20261108-110749.json`，打开文件核对 `format` / `formatVersion` / `count` / 6 个字段。
3. 手改其中一条的 `title`（例如加后缀 `-edited`），保存文件。
4. 点「导入」选该文件 → 面板显示「文件内 2 条」「将新增 0 条，覆盖同 id 的 2 条」→「确认导入」。
5. 预期：条目数不变，被改的那条标题变成 `-edited`，另一条不变；置顶与标签保留。

### 3. 合并新增

1. 在导出的文件里手工加一条全新 `id`（如 `"id": "manual-1"`，`content` 非空）。
2. 导入 → 面板显示「将新增 1 条，覆盖同 id 的 N 条」→ 确认。
3. 预期：新条目出现在列表最前，原有条目顺序不变。

### 4. 替换与回滚

1. 先导出一次留底。
2. 用一个只含 1 条的文件走「替换」→ 点两次确认。
3. 预期：列表只剩 1 条，提示「替换完成：现共 1 条」。
4. 再导入第 1 步的留底文件（替换模式）→ 预期完整恢复原条目数与内容。

### 5. 错误路径（都不应改变数据）

| 用例 | 操作 | 预期提示 |
| --- | --- | --- |
| 非法 JSON | 存一个内容为 `{oops` 的 .json 导入 | 文件不是合法 JSON，未做任何改动 |
| 外来文件 | 导入任意其它 JSON 对象（含 `format: "other"`） | 不是本插件的导出文件（format 字段不匹配） |
| 版本不符 | 把 `formatVersion` 改成 `2` | 导出文件版本为 2，当前插件只支持版本 1 |
| 缺 items | 删掉 `items` 字段 | 导出文件缺少 items 数组 |
| 空 content | 把某条 `content` 改成 `""` | 第 N 条数据无效 · 缺少内容 |
| 非对象条目 | `items` 里放字符串 | 第 N 条数据无效 · 不是对象 |
| 写入失败 | 浏览器存储写满或被禁用时导入 | 写入浏览器存储失败……已回滚，未做任何改动 |

每例执行后都确认：条目数、标题、置顶状态与本例操作前一致。

### 6. 跨机验收（真实迁移）

1. 旧机导出 → 把 JSON 拷到新机。
2. 新机装好插件，刷新页面，设置 → 提示词 → 导入 → 合并或替换 → 确认。
3. 对照旧机列表：条数、标题、正文、标签、置顶顺序一致；输入框点书本图标能搜到并插入。

## 修改

改 `client.js` 后刷新页面即可（Host 半无需重启）；改 `package.json` 的 `dsh.client`
或 `cordis.patch.yml` 需要重启 DSH。改完跑一次 `selftest.mjs`。
